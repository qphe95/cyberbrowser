## Goal
Rewrite the layout engine's core algorithm so the rendered YouTube screenshot converges toward the Chrome reference (`chrome_ref.png`, baseline MAE 0.145). Strategy: **rewrite the algorithm first, then iterate on convergence** — exactly as requested.

## Guiding constraints (from consumer-contract analysis)
- **Must preserve** the public struct fields that `display_list.cpp`, `dom_api.cpp`, and `cyberbrowser_main.cpp` read: `LayoutBox.{x,y,width,height,display,visibility,flags,background_color_*,color_*,background_image_url,border_*}`, `LayoutNodeRef.{dom_node_idx,parent_idx,first_child_idx,next_sibling_idx,prev_sibling_idx}`, `LayoutTree.{nodes,count,root_idx}`, `LayoutContext.{doc,tree,boxes,viewport_width,viewport_height,base_url,js_ctx}`.
- **Free to replace**: `LayoutNodeState` (the atomic sync fields) and the `line_x/line_y_offset/line_height` temp fields on LayoutBox — no consumer reads them. The `preorder/postorder` arrays are also internal-only.
- **Keep as-is** (already working well): the CSS cascade/matching layer (`css_parser.cpp` — just fixed), stylesheet collection, custom-property resolution, the display-list builder skeleton, and the software rasterizer.

## What's wrong today (the convergence blockers)
1. **Parallel + spin-wait model** (`layout_dispatch_chunks` with per-node atomic waits) makes the algorithm hard to reason about and forces redundant work (flex runs up to 3× via `layout_resolve_subtree`).
2. **Block flow uses parent's mutable `line_y_offset`** updated through a previous-sibling dependency — fragile; collapses when siblings are out of order or abs-positioned.
3. **Height resolution** is split awkwardly between top-down (aspect-ratio/fixed) and bottom-up (content max-bottom), with `masthead-container` collapsing to 5px and `player` to 48px.
4. **Magic-number fallbacks** for flex line cross-size (20/80) and inline boxes (80×20) produce wrong sizes.
5. **Absolute positioning** runs as a separate post-pass that can't re-flow content.

## The rewrite: a clean serial layout core (replaces ~1100 lines, lines ~1645–2770 of css_layout.cpp)

Replace the parallel top-down/bottom-up dispatch and the line-state flow model with a **single recursive, serial layout pass** driven by a `FormattingContext` per container. This is how real engines (Servo/Firefox) structure layout and is far easier to get correct and to debug.

### New internal structure (file-local in css_layout.cpp)
- `LayoutState` — pass-local scratch (replaces `LayoutNodeState`): a simple struct with the viewport, base_url, and a pointer to ctx. No atomics.
- `FormattingContext` enum: `BLOCK`, `FLEX`, `INLINE` (derived from `box->display`).
- A recursive `layout_box(ctx, idx)` that, given a node whose **parent is already positioned and sized**, does:
  1. **Resolve used width/height** against the parent's content box (reuse `layout_resolve_used_sizes`, generalized).
  2. **Position** the box within its parent's flow using a small per-child cursor passed down the sibling chain (replaces the mutable parent fields):
     - Block formatting: stack vertically (advance a `y_cursor`).
     - Flex formatting: delegate to a rewritten `layout_flex(ctx, idx)` (single-pass, no triple-execution).
     - Inline: accumulate into a line buffer (basic; text is still shaped later by display list).
  3. **Recurse into children** (depth-first) so child sizes are known before the parent's content height is finalized.
  4. **Resolve final height**: if `height` is auto, set to `max(children bottoms) - content_top` (collapsing-margin-aware). Apply min/max clamps.
  5. **Handle absolute/fixed**: resolve against the nearest positioned ancestor / viewport, and do NOT contribute to flow.
- `layout_flex(ctx, idx)`: rewrite to a single correct pass — measure items, line-break, distribute main axis (grow/shrink/basis), resolve cross axis (align-items), position. Removes `layout_resolve_subtree` and the bottom-up re-run.
- Block-flow cursor carried as a stack-local `BlockFlowCursor { double y; double x; double line_height; }`, threaded through siblings — no shared mutable parent state.

### Pipeline becomes (in `css_layout_document`)
```
1. layout_apply_stylesheet(...)        // unchanged cascade
2. layout_root(ctx): position root at (0,0), size to viewport
3. layout_children(ctx, root_idx)      // recursive: width+position top-down, height bottom-up in one DFS
4. layout_position_absolute(ctx)       // single clean pass over a collected list of abs boxes
5. set LAYOUT_HAS_LAYOUT on all; export computed geometry; dump
```
No `preorder`/`postorder` arrays, no `LayoutNodeState`, no `gc_thread_pool` dispatch in layout. (Parallelism can be re-added later as a task graph over independent subtrees if needed; correctness first.)

### Height-resolution fix (the biggest convergence win)
- Auto height = content-based, computed **after** children are laid out (natural in the recursive DFS — children complete before parent).
- Percentage height resolves against parent's **resolved** content height (now available because we go bottom-up within the DFS), fixing the collapsed containers (`masthead-container`, `player`).
- Keep the `aspect-ratio` (padding-top%) thumbnail-height technique.

### `css_layout_run` cleanup
- Remove the hardcoded `base_url = "https://www.youtube.com/"` (line 2919); derive from the document/location instead (or accept it's a smoke-test default and leave a clear comment). Decision point for convergence phase.

## Sequencing (rewrite first, then converge)

**Step A — Rewrite (this plan):**
1. Add `LayoutState` + formatting-context helpers; keep old functions compilable beside them.
2. Implement `layout_box` / `layout_children` / `layout_flex` (serial).
3. Switch `css_layout_document` to call the new serial pipeline; delete the old `layout_dispatch_chunks`, `layout_top_down_node`, `layout_bottom_up_node`, `layout_resolve_subtree`, and the old `layout_flex_container`.
4. Remove the `LayoutNodeState` allocation and the atomic waits from layout.
5. Build clean (warnings ok), confirm it runs end-to-end and produces a screenshot (not necessarily matching yet).

**Step B — Convergence (after rewrite is in and building):**
Iterate with the `chrome_ref.png` + MAE metric as the oracle:
- Fix the player region (dark background / poster positioning).
- Fix masthead bar height/position.
- Fix body background resolution (the synthetic `#909090`).
- Tune flex/percent-height for the watch-page columns.
Each sub-fix: rebuild, capture screenshot, compute MAE, keep if it improves.

## Risk & mitigation
- **Risk**: breaking the working (post-fix) blank-screen-free state. **Mitigation**: keep the change confined to css_layout.cpp internals; the public struct contract is preserved so display_list/dom_api/main need no changes. Verify after Step A that the screenshot still has content (non-white %).
- **Risk**: a serial DFS over a deep YouTube DOM could stack-overflow. **Mitigation**: the executable already sets a 64 MiB stack (CMakeLists link flag); monitor depth, and convert the DFS to an explicit stack if needed.
- **Risk**: removing parallelism slows the run. **Mitigation**: acceptable for now (the cascade is already the dominant cost); parallelism is orthogonal to correctness and can return later.
