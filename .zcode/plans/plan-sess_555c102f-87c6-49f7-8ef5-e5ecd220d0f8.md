## Goal
Let the ShadyDOM `webcomponents-sd.js` polyfill **own** shadow DOM, instead of implementing native shadow DOM + compensating with workarounds. YouTube's inline config sets `window.ShadyDOM={force:true,preferPerformance:true,noPatch:true}`, which forces the polyfill active (`inUse=true`) **unconditionally** — `force:true` short-circuits all feature detection. So the polyfill will always activate regardless of whether our native `attachShadow` exists.

## Strategy
Remove every workaround that fights the polyfill, plus the native shadow DOM that competes with it. Keep only the **DOM mutation/traversal primitives** the polyfill builds on (these are already implemented and working — the "contract").

## Changes

### 1. Remove native Shadow DOM that competes with the polyfill
**`src/browser_api_impl.cpp`** (~lines 3585-3627): Delete the native `attachShadow` registration on `HTMLElement.prototype` and `Element.prototype`, and the native `ShadowRoot` class/proto wiring. Keep a bare `ShadowRoot` **constructor + minimal prototype** as a global (the polyfill does `b.__proto__=ShadowRoot.prototype` and `instanceof ShadowRoot`), but remove the C-backed getters/host/mode/innerHTML logic — the polyfill supplies its own.

### 2. Remove the neutral ShadyDOM stub
**`src/browser_api_impl.cpp`** (~lines 3752-3828): Delete the entire `shady_dom_js` IIFE that installs a fake `window.ShadyDOM` with `inUse:false`. Let the page's own inline config stand.

### 3. Remove per-script + final neutralization
**`src/js_quickjs.cpp`** (~lines 2936-2982): Delete both `<shady_neutral>` JS_Eval blocks that force `ShadyDOM.force=false; inUse=false` after every script and at the end. This was repeatedly defeating the polyfill.

### 4. Remove `js_dom_restore_native_methods` clobbering (CRITICAL)
**`src/browser/dom_api.cpp`** (lines 932-960) + declaration in `browser_api_impl_types.h` (412-415): This re-binds `appendChild`/`insertBefore`/etc. to raw C functions after every script, **clobbering the polyfill's wrappers**. Remove the `__shady_native_*` re-binding and the calls to this function. Keep the native methods on the prototype (they're the base the polyfill captures via its own `E()` descriptor-copy into `__shady_native_*`).

Call sites to remove: `js_quickjs.cpp:2934` (per-script), `js_quickjs.cpp:2967` (final), `cyberbrowser_main.cpp:702`.

### 5. Remove `dom_sync_shady_tree` + `shady_ensure_obj`
**`src/browser/dom_api.cpp`** (lines 1917-1957), declaration in `browser_api_impl_internal.h:187`: The polyfill maintains its own `__shady` tree via its `xc()` sync. Remove our manual mirroring. Remove the call in `js_node_cloneNode_real` (dom_api.cpp:1774) and in `js_element_attach_shadow` (which is itself being removed).

### 6. Remove source-rewriting patches
**`src/html_media_extract.cpp`** (~lines 900-1090): Delete these functions entirely — they rewrite YouTube's minified JS to work around the neutralized polyfill:
- `apply_youtube_e19_null_guard_patch`
- `apply_youtube_scoped_root_patch`
- `apply_youtube_dom_patch_patch`
- `apply_youtube_shadydom_use_patch`
- `apply_shadydom_matches_patch`

Remove their invocations at the patch orchestration site (~lines 1186-1192), keeping only `apply_youtube_page_token_patch` (unrelated to shadow DOM).

### 7. Simplify `is_unsafe_external_script`
**`src/html_media_extract.cpp`** (lines 832-849): Remove the shadow-DOM-specific URL blocklist entries that were there to compensate (`webcomponents-sd-shadycss`, `webcomponents-all-noPatch`). Keep `custom-elements-es5-adapter` skip only if still needed. Let `webcomponents-sd.js` run unmodified.

### 8. Remove diagnostics
**`src/cyberbrowser_main.cpp`** (~lines 724-820): Delete the `[SHADY-NEUTRAL]` neutralization block (724-733), `[PRE-LOAD-DIAG]` (735-743), and the massive `[SHADY-DIAG]` IIFE (770-820). Remove the commented-out `disable_shady_js` (682-686).

## What stays (the "contract" — already working)
All of these are implemented and the polyfill relies on them via `__shady_native_*`:
- **Node mutation**: `appendChild`, `insertBefore`, `removeChild`, `replaceChild`, `cloneNode`
- **Node traversal**: `parentNode`, `firstChild`, `lastChild`, `previousSibling`, `nextSibling`, `childNodes`, `parentElement`, `textContent`, `getRootNode` (composed-aware)
- **Element**: `getAttribute`, `setAttribute`, `hasAttribute`, `removeAttribute`, `matches`, `closest`, `querySelector`, `querySelectorAll`, `children`, `childElementCount`, `innerHTML`
- **Document**: `importNode`, `getElementById`, `createElement`, `elementFromPoint`
- **Events**: `addEventListener`/`removeEventListener`/`dispatchEvent`

## Verification
After changes: rebuild, run `./cyberbrowser`, confirm the polyfill's `attachShadow` replacement is reached (the `[ATTACH-SHADOW-ENTER]` native log should **disappear** since we removed native attachShadow; the polyfill's own code runs instead), `ytd-app.connectedCallback` no longer throws "not a function", and elements report `shadowRoot=yes`.

## Risk / iteration note
The polyfill's `shadyUpgradeFragment` path calls `b.host.__shady_native_appendChild(b)` where `b` is a JS wrapper object, not a real DOMNode. Our `appendChild` may need a guard to handle non-DOM-node children gracefully (skip DOM-linking, no throw). I'll address this if it surfaces during verification rather than preemptively, to avoid over-engineering.
