## Goal
Unify the two duplicate CSS pipelines so there is ONE stylesheet collection + selector matching pass, with the layout engine as the single consumer for rendering.

## Background
There are currently two completely separate CSS pipelines that duplicate collection, fetching, and matching:

1. **css_parser.cpp** (`css_apply_document_styles`): Collects/fetches stylesheets, matches selectors, writes results to JS `element.style` objects + a lock-free computed-style table for `getComputedStyle()`. Requires `has_js_object` on nodes (which the rebuilt document doesn't have). Has a hardcoded 1024px viewport for media queries.

2. **css_layout.cpp** (`layout_apply_stylesheet`): Re-collects/re-fetches the SAME stylesheets, re-matches selectors independently, writes results to `LayoutBox` fields for rendering. Has the real viewport width. Also handles UA stylesheet, constructed stylesheets, custom properties, and pseudo-elements — features the parser pipeline lacks.

The layout pipeline is strictly more capable. The parser pipeline's only unique output is JS-visible computed styles (for `getComputedStyle()` and runtime JS style queries). Its `has_js_object` gate causes it to silently skip ALL elements in the rebuilt document.

## Plan

### Step 1: Remove `css_apply_document_styles` call from the post-script rebuild path
**`cyberbrowser_main.cpp`** (~line 820): Remove the `css_apply_document_styles(g_ctx, js_doc, doc, css_base)` call. The layout engine (`css_layout_run` inside `render_document_to_jpg`) already has its own complete CSS pipeline that produces correct results. This call was redundant AND broken (skipped all nodes due to missing `has_js_object`).

### Step 2: Remove `css_apply_document_styles` call from the pre-script path
**`js_quickjs.cpp`** (~line 2826): Remove the `css_apply_document_styles` call before scripts run. The pre-script styles aren't needed for rendering (the layout runs on the post-script rebuilt document). If JS code queries `getComputedStyle()` during script execution, it will still work via the existing `css_computed_*` table (which is populated lazily). The pre-script CSS application was fetching stylesheets twice — once here and once during layout.

### Step 3: Remove the duplicate code from css_parser.cpp
Delete these functions from `css_parser.cpp` (they are now dead code — no callers after Steps 1+2):
- `css_fetch_stylesheet` (line ~792) — duplicate of `layout_fetch_stylesheet`
- `css_resolve_url` (the URL resolver used only by `css_fetch_stylesheet`)
- `css_find_host_tag` (line ~866) — duplicate of `layout_find_host_tag`
- `css_collect_stylesheets_recursive` (line ~1040) — duplicate of `layout_collect_stylesheets_recursive`
- `css_match_one_node` (line ~1088) — duplicate of `layout_collect_matched_declarations`
- `css_match_node_styles_job_impl` (line ~1149) — the JS-application worker
- `css_apply_node_styles_parallel` (line ~1243) — the orchestrator
- `css_apply_document_styles` (line ~1349) — the entry point
- `CssSheetList` / `css_sheet_list_add` / `css_sheet_list_free` (line ~816) — duplicate container
- `CssElementResult`, `CssMatchJob` structs — vestigial parallel-matching scaffolding

Keep in `css_parser.cpp`:
- All CSS parsing primitives (`css_stylesheet_parse`, `css_parse_declaration_block`, `css_parse_simple_selector`, `css_parse_selector_chain`)
- All selector matching primitives (`css_selector_matches`, `css_selector_matches_one`, `css_simple_matches`, `css_chain_matches`)
- `css_specificity_from_selector_text` and helpers
- `css_rule_media_matches`
- `css_parse_inline_style` and `css_declarations_free`
- `css_scope_stylesheet` and `css_stylesheet_free`
- `css_set_style_property`, `css_ensure_style_object`, `css_apply_declarations` (still used for JS-visible styles when needed)
- All computed-style table functions (`css_computed_*`, `css_ensure_computed_style`) — used by `getComputedStyle()`
- `css_apply_inline_style` (used by inline style setter on JS elements)
- Remove the declaration from `css_parser.h` for `css_apply_document_styles`

### Step 4: Remove the constructed-stylesheet injection from cyberbrowser_main.cpp
**`cyberbrowser_main.cpp`** (~line 795-805): Remove the `adoptedStyleSheets` JS injection block. The layout engine already has `layout_collect_constructed_stylesheets` which reads adopted stylesheets directly from JS during its own collection pass. The injection was a workaround for the parser pipeline's inability to see adopted stylesheets.

## What stays unchanged
- The layout engine's pipeline (`css_layout.cpp`) remains the single CSS authority for rendering
- `getComputedStyle()` continues to work via the computed-style table (populated lazily per-element when queried)
- All CSS parsing, selector matching, and declaration parsing primitives stay in `css_parser.cpp`
- The `css_api.cpp` CSSStyleSheet/replaceSync implementation is unaffected
